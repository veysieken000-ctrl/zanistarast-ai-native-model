# Zanistarast.com — Likes and Personalization

Status: LOCKED — Roadmap item 19

## Principle

Personalization helps a visitor discover more admitted works that fit their interests. It does not decide what is true, moral, publishable or authoritative.

A Like means “I want more like this” as a preference signal. It is not a Rasterast vote, scientific endorsement, religious judgment or publication approval.

## Interaction signals

The future system may use signals such as:

- explicit Like / unlike;
- Save / Watch later;
- completed or partially viewed works;
- voluntarily followed themes/collections;
- language preference;
- chosen audience/context settings;
- explicit “show me less like this” feedback;
- search and navigation choices where privacy rules permit.

Passive engagement signals should have less authority than explicit user choices and must not be optimized into compulsive-consumption mechanics.

## Preference profile

A user preference profile may learn affinity to:

- themes/values;
- media formats;
- languages;
- cultures/regions/collections;
- creators/source traditions where appropriate;
- duration/reading depth;
- audience context.

These are discovery preferences only. They cannot mutate canonical WORK, SOURCE, REVIEW_RECORD, RIGHTS_RECORD or publication metadata.

## Similar-content behavior

When a visitor likes a work, recommendation may increase eligible works sharing meaningful attributes such as theme, narrative form, collection, language or source/cultural context.

Similarity should be explainable enough to support statements such as “Because you liked stories about honesty” rather than relying only on opaque engagement correlation.

The system must preserve diversity: liking one theme must not permanently trap the visitor inside it.

## Eligibility before ranking

Recommendation is a two-stage process:

1. ELIGIBILITY — determine which works are allowed to be shown in the visitor's context.
2. RANKING — order those eligible works using relevance and preference signals.

Ranking can never make an ineligible work eligible.

Eligibility may include:
- PUBLISHED/admitted state;
- Rasterast state;
- rights state;
- audience/context suitability;
- language availability;
- withdrawal/correction state;
- cultural/moral publication constraints.

## Governing boundary

Within this project's framework, no popularity, like count, completion rate, similarity score or personalized preference may override the applicable Qur'anic-ruling and Prophetic-ethics publication constraints.

The recommendation engine must consume admitted content; it must not become a parallel publication authority.

## Like counts

If public like counts are later shown, they represent engagement only. They must not be styled or described as evidence of truth, virtue, scientific quality or religious authority.

The product may choose not to expose public counts while still using private preference signals.

## New and anonymous users

The platform must remain useful without an account or historical profile. New/anonymous visitors may receive:

- editorial collections;
- values-based discovery;
- currently relevant admitted works;
- language/context defaults chosen explicitly or from non-sensitive settings;
- search and browse.

Personalization should improve discovery, not become a prerequisite for access.

## User control

Where implemented, visitors should have understandable controls to:

- unlike/remove an explicit preference;
- clear or reset recommendation preferences where applicable;
- choose language/context;
- ask for less similar content;
- browse outside personalization through search/categories/editorial collections.

The system should not pretend a user preference has been deleted if underlying retention obligations require otherwise; product privacy policy and implementation must define actual retention behavior.

## Sensitive inference boundary

The recommendation system should avoid inferring sensitive personal traits merely to improve engagement. It should primarily learn content preferences from content interactions.

It must not infer religious belief, ethnicity, health, political ideology or other sensitive identity as a hidden targeting category from viewing behavior.

A user's interest in a cultural or religious work does not establish that the user belongs to that culture/religion.

## Children and families

For child/family contexts, audience eligibility and safety rules precede personalization. A child-oriented profile cannot be recommended adult-context material merely because engagement similarity is high.

The product should avoid manipulative streaks, pressure, scarcity, shame or reward loops aimed at keeping children continuously engaged.

## Data minimization

Store only preference data needed for the product purpose, with clear separation from canonical content truth/provenance. Identifiers and retention should be designed later under the privacy/security architecture.

Recommendation development should prefer aggregate/non-sensitive evaluation where individual identity is unnecessary.

## Evaluation

Recommendation quality should not be measured only by watch time. Future evaluation should include:

- relevance to explicit preferences;
- successful discovery across admitted themes;
- diversity/non-repetition;
- audience suitability;
- avoidance of withdrawn/ineligible content;
- user ability to control recommendations;
- performance without manipulative engagement tactics.

## Item 19 acceptance criteria

1. Like is defined as a preference signal only.
2. Preference data is separated from canonical content/review data.
3. Similar works can be recommended by meaningful attributes.
4. Eligibility is computed before ranking.
5. Ranking can never admit prohibited/unreviewed content.
6. Qur'anic-ruling and Prophetic-ethics publication constraints remain above personalization.
7. Public like counts, if shown, are not authority scores.
8. Anonymous/new users retain useful non-personalized discovery.
9. Users can move outside their personalized feed.
10. Sensitive identity is not inferred from content interest for targeting.
11. Child/family eligibility precedes engagement similarity.
12. Data collection is minimized to the recommendation purpose.
13. Recommendation quality is not reduced to watch-time maximization.
